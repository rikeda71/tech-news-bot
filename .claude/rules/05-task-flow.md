# タスクフロー

ユーザーから新しいタスクを受けたら、コードに手を付ける前に **必ず GitHub issue を作成** し、計画を投下してから着手する。

## issue 作成手順

1. `gh issue create` でタイトルと本文を指定 (本文は HEREDOC 推奨)
2. タイトル: `[task] <概要>` を基本形 (bug fix なら `[bug]`, 調査なら `[investigation]`)
3. 本文テンプレート:

   ```
   ## 背景 / 目的
   なぜやるか / ユーザーからの要望

   ## 計画
   - 影響範囲のファイル
   - 実装ステップ
   - 検証方法 (テスト追加 / 手動確認など)

   ## 完了条件
   - [ ] vp check pass
   - [ ] vp test run pass
   - [ ] (該当すれば) 動作確認
   ```

4. 発行された issue 番号を控え、対応 PR の本文に `Closes #<n>` を入れる

## 例外 (issue 不要)

- typo / コメント追加など 1 行で完結する些細な修正
- 設定ファイルの値を 1 つ変えるだけのもの
- ユーザーが明示的に「issue 不要」と指示した場合
- このルール自体の変更など、ルール / ドキュメントの即時反映

判断に迷ったら作る側に倒す。
