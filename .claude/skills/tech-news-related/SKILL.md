# tech-news-related

## 他の skill との使い分け

- **tech-news-digest**: 今日・今週・任意期間の記事を素早くリスト形式でまとめる。デイリーチェックや「何があった？」程度の確認に最適。
- **tech-news-weekly**: 週次・月次を「読み物」として仕上げる。テーマ別ストーリー・前週との比較が必要な場合はこちら。
- **tech-news-search**: 特定キーワードで深掘り検索。「MCP の最近の話題は？」のようなキーワード絞り込みにはこちら。
- **tech-news-summary**: 単一記事の本文を深く読み込んで詳細要約を生成する。ピボット記事自体を深く理解したい場合はこちら。
- **tech-news-related (本 skill)**: ピボット記事 1 本を中心に、D1 から関連記事を探して関係性を解説する「文脈マップ」が必要な場合に使う。

## やること

ピボット記事 (URL or タイトル文字列) を受け取り、D1 (`articles` テーブル) から関連記事候補を抽出してスコアリングし、関係性ラベル + 理由付きの文脈マップを生成する。

## 入力

| 引数                  | 必須 | デフォルト | 説明                     |
| --------------------- | ---- | ---------- | ------------------------ |
| ピボット記事          | 必須 | —          | URL またはタイトル文字列 |
| `--since=week\|month` | 任意 | `month`    | D1 の検索期間            |
| `--limit=N`           | 任意 | `5`        | 関連記事の表示件数上限   |

## 手順

### Stage 1: ピボット解決 — 記事を D1 で特定

`tools/d1-client/recent.mjs` を Node から実行してピボット記事を特定する。

```sh
node tools/d1-client/recent.mjs --since=month --target=remote
```

取得した JSON の `articles` 配列から以下の方法でピボット記事を照合する:

- **URL 入力の場合**: `articles[].url` と完全一致で検索する
- **タイトル文字列の場合**: `articles[].title` と大文字小文字を区別せず部分一致で検索する

照合できない場合:

- D1 に未収録の旨を正直に報告する
- URL 入力の場合は WebFetch でページにアクセスし、タイトルと本文概要を取得して「未収録の記事」として処理を続行する (取得失敗時は中断)
- タイトル入力の場合は似た記事が存在すれば候補を提示し、ユーザーに確認を促す

### Stage 2: キーワード抽出 — ピボット記事の特徴語を抽出

ピボット記事の `title` と `summary` から以下の種類の特徴語を抽出する:

- 固有名詞・プロダクト名 (例: "ADK Go", "Gemma 4", "YJIT", "Subagents")
- 技術用語・フレームワーク名 (例: "MCP", "WebAssembly", "Rust async")
- 組織名・サービス名 (例: "Google DeepMind", "OpenAI", "Vercel")
- 概念キーワード (例: "inference", "fine-tuning", "edge computing")

抽出した特徴語リストを Stage 3 のスコアリングに使う。

### Stage 3: D1 で関連記事候補を抽出 & スコアリング

Stage 1 で取得した `articles` からピボット記事自身を除いた全件をスコアリング対象とする。

各候補記事に以下のシグナルでスコアを加算する:

| シグナル                                                    | 加点 |
| ----------------------------------------------------------- | ---- |
| タイトルに特徴語が含まれる (1 語につき)                     | +3   |
| summary に特徴語が含まれる (1 語につき)                     | +2   |
| `feed_id` がピボットと同一 (同シリーズ)                     | +4   |
| `category` がピボットと同一かつ `published_at` が ±3 日以内 | +3   |
| `author` がピボットと同一 (author が非 null の場合)         | +4   |
| `category` がピボットと同一                                 | +1   |

スコアが 0 の記事はリストから除外する。

### Stage 4: 重複排除と上位 N 件の選定

Stage 3 のスコア順に並べ、以下の条件で選定する:

- 上位 `--limit` 件 (デフォルト 5 件) を抽出する
- 同一 URL はピボット含め除外する (Zenn de-dup と同様の処理)
- 同一 `feed_id` からは最大 2 件まで (特定フィードへの偏り防止)

関連記事が 0 件の場合は正直に報告し、creative writing で埋めない。`--since=month` を試していなければ提案する。

### Stage 5: 関係性ラベル付け + 文脈マップ生成

**関係性ラベルの判定**:

各関連記事に以下のラベルのうち最も適切な 1 つを付ける。タイトル比較だけで断定しない — 必要に応じて `url` を WebFetch して内容を確認する (最大 3 回まで)。

| ラベル               | 判定基準                                         |
| -------------------- | ------------------------------------------------ |
| 直接の続報           | 同一トピックの後続イベント・発表                 |
| 同テーマの別視点     | 同じ技術・製品を別の角者・角度で論じている       |
| 反対意見 / 批評      | ピボット記事の主張や発表に対する批判・懐疑的見解 |
| 同シリーズ           | 同一フィード内の連載・シリーズ記事               |
| 同著者               | 同じ著者による別記事                             |
| 同カテゴリ周辺話題   | 同カテゴリで同期間の関連トレンド記事             |
| 同期間の関連トレンド | 同時期に盛んに議論されていた関連テーマ           |

**文脈マップ**:

選定した関連記事全体を俯瞰して、ピボット記事がどのような流れの中に位置付くかを 2〜4 段落で記述する。

- ピボット記事の背景・文脈を簡潔に示す
- 関連記事との繋がりをストーリーとして描く
- 業界全体のトレンドとの関係に言及する

## webfetch_blocklist

以下のホストは WebFetch (Stage 5 の関係性確認) をスキップし、`summary` ベースでラベル判定する:

| ホスト       | 理由                                             |
| ------------ | ------------------------------------------------ |
| `openai.com` | Cloudflare Bot Management により WebFetch が 403 |
| `medium.com` | paywall / ログイン wall で本文取得不可           |

除外判定は `new URL(article.url).hostname` で行う。

## 出力フォーマット

```md
# Tech News Related — "<ピボット記事タイトル>"

## ピボット記事

**[<タイトル>](url)** _(<feed_name>, <category>, <YYYY-MM-DD>)_

<ピボット記事の 2〜3 文による位置付け。どのような発表/議論で、なぜ注目されているかを書く>

## 関連記事 (N 件)

### 1. [<タイトル>](url)

_<feed_name> / <category> / <YYYY-MM-DD> — ラベル: **<関係性ラベル>**_

<なぜ関連するかを 1〜2 文で説明。記事の内容に基づいて書く>

### 2. [<タイトル>](url)

_<feed_name> / <category> / <YYYY-MM-DD> — ラベル: **<関係性ラベル>**_

<なぜ関連するかを 1〜2 文で説明>

<!-- --limit=N 件分続ける -->

## 文脈マップ

<ピボット記事と関連記事を俯瞰して、この流れ全体の文脈を 2〜4 段落で説明する>
```

D1 に未収録の記事をピボットとした場合は、冒頭に `> この記事は D1 に未収録です。WebFetch で取得した情報を元に処理しています。` を付ける。

## ガードレール

- **関連記事 0 件**: 正直に報告する。creative writing で埋めない。`--since=month` 未使用なら提案する
- **ピボット未解決**: タイトル部分一致で複数ヒットした場合は候補リストを提示してユーザーに選択を促す
- **WebFetch 連続失敗**: 関係性確認の WebFetch が 3 回とも失敗した場合は `summary` ベースのみで処理し、出力末尾に `_注: WebFetch が失敗したため summary ベースでラベルを判定しています_` を付ける
- **同一 URL 除外**: ピボット記事と同一 URL の記事は関連リストに含めない
- **PII / 機密情報**: author 名以外の個人情報が混ざっていたら出力から除外する
- **D1 接続失敗**:
  - `--target=remote` で 401/403 → `pnpm --filter @tnb/web exec wrangler login` を案内
  - `--target=local` で 0 件 → `pnpm migrate:local` + `pnpm dev` でローカル収集を 1 回回すよう案内
